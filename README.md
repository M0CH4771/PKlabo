# PKlabo — ポケカ買取ラボ オンラインショップ

GitHub Pages（画面）＋ Cloudflare Workers ＋ D1（API・データ）で動く、自前のECサイトです。

国内の主要カードショップEC（遊々亭・カードラッシュ・晴れる屋2・ドラゴンスター等）と TCGplayer を調べ、それぞれの強みを取り込みつつ、どこにもない機能を足しています。

**お客さん向け**
- デッキリストを貼るだけで、在庫から一番安い（または状態の良い）組み合わせをまとめてカートへ
- 同じカードの状態違い（A / B / PSA10 …）を1画面で比較
- 価格推移グラフ、セール表示（値下げ前価格・割引率）
- 商品ページに買取価格を表示して、買取フォームへ誘導
- 高機能な絞り込み（弾・レアリティ・状態・価格帯・セール・実物写真）、ひらがな／カタカナ・全角／半角を区別しない検索
- 実物写真の複数枚表示、在庫数・残りわずか表示
- ログイン不要のお気に入り（登録後に値下がりするとお知らせ）、最近見た商品、売れ筋ランキング
- 入荷通知メール（在庫を戻した瞬間に自動送信）
- 即日発送の締め切りカウントダウン、送料無料まで残りいくらかのバー
- 店頭受け取り（送料無料）、クーポン、配送会社の追跡リンク、注文状況のステップ表示、ブラウザ内の注文履歴
- 支払い：銀行振込（前払い）。Stripe のキーを登録するとカード払いが追加されます

- 会員登録・ログイン・マイページ（注文履歴・住所保存・パスワード再設定・退会）
- ポイント制度（登録ボーナス・還元率・付与タイミング・有効期限・注文での利用・キャンセル時の返却）
- オリパ：総口数・賞ごとの封入数と封入率・全体の残り口数を公開（賞ごとの残り数は非公開・管理画面のみ）、ラストワン賞、当選履歴の公開（ON/OFF可）。当選品は実物発送のみ（ポイント・コイン等への交換なし）
- パックを選んで開ける（ボード形式）：総口数ぶんのパックが番号つきで並び、お客様が選んで開封。開けられたパックには中身が表示される。中身は開けた瞬間にサーバーで抽選（どれを選んでも確率は同じ）。オリパごとにON/OFF、コイン方式のときに使用、2,000口まで
- 引く回数：「1回引く」「10回引く」「選択した回数引く」。オリパごとに設定した口数以下になると「残り全部引く」（1回の上限に関係なく残りを全部）
- コインでオリパ：コインを購入（カードは即時付与・振込は入金確認後）→ オリパのページで「コインで引く」→ その場で開封演出 → 当選カードは「獲得カード」に貯まり、まとめて発送依頼。有効期限は既定6か月（資金決済法の前払式支払手段の届出対象外）。コイン機能をOFFにすると、オリパも商品と同じように注文・入金確認後に開封する方式になります
- 電話番号（SMS）認証：1番号1アカウント、登録ボーナスやオリパ購入の条件にできる（Twilio Verify を使用・任意）
- 状態違い（A / B / PSA10 …）を1枚のカードとしてまとめて表示し、商品ページで状態を切り替え

**お店向け（管理画面）**
- ダッシュボード（売上・30日グラフ・売れ筋・入荷待ちの多い商品）
- 注文処理：入金確認 → 発送（配送会社＋追跡番号）→ 自動メール。キャンセルで在庫・クーポンを自動で戻す
- ピッキングリスト・納品書の印刷、発送用CSV
- スマホで撮った写真をそのままアップロード（ブラウザで自動圧縮）、商品の複製、CSV一括登録・書き出し
- クーポン（％引き・円引き・最低金額・回数上限・期限）
- **設定タブで全部カスタマイズ**：機能ごとのON/OFF、ショップ名・ロゴ文字・テーマカラー・お知らせバナー、送料・発送曜日・締め時刻、店頭受け取り、振込先、ポイント率・ボーナス・有効期限、オリパの注意書き、カテゴリ、状態表記の説明、特定商取引法の表記
- 商品は「カード」ごとに状態違いをまとめて管理（＋状態で追加、カード名などの共通情報は一括反映）
- CSV 入出力：全項目／在庫・価格だけを書き出し → Excel 等で編集 → 読み込み。ID で更新・ID なしは追加、「更新だけ」モード、在庫の上書き／加算、型番＋状態での照合。Shift_JIS の CSV もそのまま読めます
- 会員管理（検索・ポイント／コイン調整・CSV書き出し）、ダッシュボードにコイン販売額・未使用コイン残高・獲得カードの未発送枚数、オリパ管理（作成・賞品の写真・還元率の目安・当選履歴）
- 在庫は注文した瞬間に確保、入金期限切れで自動キャンセル（15分ごと）

## 公開までの手順

必要なもの：Cloudflare アカウント（無料）、パソコンの Node.js 20 以上、このリポジトリ。

### 1. API（Cloudflare Worker）を作る

```bash
git clone https://github.com/M0CH4771/PKlabo.git
cd PKlabo/worker
npx wrangler login                                   # ブラウザで Cloudflare にログイン
npx wrangler d1 create pklabo-db                     # 表示された database_id を wrangler.toml に貼る
npx wrangler d1 execute pklabo-db --remote --file=schema.sql
```

### 2. 管理画面の鍵を登録する（秘密の値は GitHub に置かない）

```bash
openssl rand -base64 30                               # ← 出てきた文字列を管理キーにする（パスワード管理アプリに保存）
npx wrangler secret put ADMIN_KEY                     # 上の文字列を貼る（20文字以上必須）

```

（任意）2段階認証を追加する場合：`node ../scripts/totp-secret.mjs` で秘密鍵を作り、スマホの認証アプリ（Google Authenticator など）の「セットアップキーを入力」と `npx wrangler secret put ADMIN_TOTP_SECRET` の両方に登録します。以後、管理画面へのログインは「管理キー＋アプリの6桁コード」になります。

### 3. デプロイ

```bash
npx wrangler deploy                                   # 表示された https://pklabo-api.〇〇.workers.dev を控える
```

### 4. 画面（GitHub Pages）を公開する

1. `docs/config.js` の `API_BASE` を手順3の URL に書き換えて commit / push
2. GitHub のリポジトリ → Settings → Pages → Branch: `main`、フォルダ: `/docs` → Save
3. 数分後に `https://m0ch4771.github.io/PKlabo/` で公開されます（管理画面は `/admin.html`）
4. `worker/wrangler.toml` の `SITE_URL` と `ALLOWED_ORIGIN` が公開URLと合っているか確認（違えば直して再デプロイ）

### 5. 管理画面で初期設定

`/admin.html` にログイン →「設定」タブ：
- 振込先（**公開リポジトリに口座情報を書かないため、ここで入力**）
- 特定商取引法の表記（販売業者・責任者・所在地・電話・メール）
- 送料・送料無料ライン・発送曜日・締め時刻・店頭受け取り
- ポイント・オリパ・各機能のON/OFF、テーマカラー、お知らせ

### 6. 商品登録 → テスト注文

1. 「CSV入出力」で空のテンプレートを書き出し → スプレッドシートで入力 → 読み込み（または「商品」タブで1件ずつ）
2. 自分で振込のテスト注文 → 管理画面で「入金確認」→「発送済み」→ 状態がお客様ページに反映されるか確認 → キャンセルして在庫が戻るか確認

### 7. 法令まわり

- **古物商のURL届出**：中古品をネットで売るので、公開URLを許可を受けた警察署経由で届け出る
- **オリパ**：オンラインオリパは法的にグレーな分野です。販売前に弁護士に確認することをおすすめします（設計上の配慮は下の「セキュリティ」参照）

### 8. 必要になったら（任意）

| 設定 | 内容 |
| --- | --- |
| メール送信 `RESEND_API_KEY` / `MAIL_FROM` | Resend（無料枠あり）でドメイン認証して登録。注文・入金・発送・入荷通知・会員のメール確認・パスワード再設定が自動で届くようになります。**会員の登録ボーナスはメール確認後に付与**されるので、会員・ポイントを使うなら設定推奨 |
| 電話番号認証 `TWILIO_ACCOUNT_SID` / `TWILIO_AUTH_TOKEN` / `TWILIO_VERIFY_SID` | Twilio に登録 → Verify でサービスを作成（Service SID が `VA…`）→ 3つを `wrangler secret put` → 管理画面「設定」で電話番号認証をON。料金は認証成功1件 $0.05＋日本宛SMS 1通 $0.08前後（1回20円前後）。Twilio 管理画面の Fraud Guard と、送信先の国を日本だけに制限する設定もONにしてください |
| カード決済 `STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` | Stripe の審査が通ったら登録。Webhook は `https://<worker>/api/stripe/webhook` に `checkout.session.completed` と `checkout.session.expired` |

| `ADMIN_EMAIL` / `DISCORD_WEBHOOK_URL` | 新規注文の通知先 |

## 日々の運用

1. 振込の照合：通帳・ネットバンクの振込名義の先頭6桁（注文番号）で照合 →「注文」タブで「入金確認」（オリパはこの時点で開封可能に）
2. 発送：「発送待ち」でピッキングリスト・納品書を印刷 → 梱包 → 追跡番号を入れて「発送済み」（ポイントはここで付与）
3. 期限内に入金がない注文は自動で「期限切れ」になり、在庫・オリパ・ポイント・クーポンが戻ります
4. コイン購入（振込）は「入金確認」でコインが付与され完了。獲得カードの発送依頼は「オリパ当選品の発送」として発送待ちに並ぶので、通常の注文と同じように追跡番号を入れて「発送済み」に
4. 在庫の入荷はCSVの「在庫に加算」モードでまとめて反映できます

## セキュリティ

**組み込み済みの対策**
- 管理画面：管理キー（20文字以上）＋2段階認証（任意）、5回失敗で15分ロック（全体でも1時間30回まで）、ログインは12時間で失効、管理キーはブラウザに保存しない、操作履歴（設定タブの下）
- 会員：電話番号（SMS）認証で1番号1アカウント（任意）、SMS送信は日本の携帯番号のみ・1アカウント1時間5回／1番号3回／全体300回までに制限（SMS料金の水増し攻撃対策）、パスワードは PBKDF2（10万回）でハッシュ化、ログイン失敗は1アカウント10回・1IP20回でロック、登録は1IP1時間5件まで、パスワード変更で他端末をログアウト、メール確認後に登録ボーナス
- 注文：金額はすべてサーバーで計算、注文確認ページは推測できないトークンが必要、未入金の振込注文は1人3件まで、注文は1IP1時間15件まで
- オリパ：抽選はサーバーの暗号論的乱数、賞ごとの残り数は非公開（入金前に中身を推測して払わない「引き直し」を防止）、販売開始後は封入内容を変更不可、当選品のポイント・コイン交換なし、コインは購入分を先に期限の近い順に消費、残高不足のときは抽選しない（1回の処理で残高チェックと減算）
- 画面：Content-Security-Policy でインラインスクリプトを禁止、表示する文字はすべてエスケープ、書き出すCSVは Excel の数式実行を無効化
- API：SQL はすべてプレースホルダー、Stripe Webhook は署名を検証、個人情報を含む応答はキャッシュさせない、セキュリティヘッダー付き

**運用で守ってほしいこと**
- 管理キー・2段階認証の秘密鍵・Stripe/Resend のキーは GitHub やチャットに貼らない（`wrangler secret put` でだけ登録）
- Cloudflare・GitHub・Stripe のアカウントにも2段階認証を設定する
- 管理画面は共用PCで使わない。使い終わったらログアウト
- 「設定」タブの操作履歴に覚えのない操作やログイン失敗の急増がないか、ときどき確認する
- もし管理キーが漏れたら：`npx wrangler secret put ADMIN_KEY` で新しい値に変えて再デプロイ（既存のログインは12時間以内に切れます）
- D1 は過去7日分（無料プラン）まで任意の時点に戻せます（Time Travel）。大きな作業の前は `npx wrangler d1 export pklabo-db --remote --output=backup.sql` でバックアップ

## Cloudflare 無料プランについて

無料プランは「1回の処理で D1 に問い合わせできるのは50回まで」です。CSV 読み込みは100行ずつ分けて送信、オリパは口数によらず数回の問い合わせで抽選、入金期限切れの自動キャンセルは1回5件ずつ処理するようにしてあります。商品数・注文数が大きく増えたら Workers Paid（月5ドル〜）を検討してください。

## CSV 一括登録の形式

1行目に見出し（日本語でもOK）：

```
商品名,弾,型番,レアリティ,状態,カテゴリ,価格,値下げ前価格,買取価格,在庫,画像URL,説明,実物写真
リザードンex,黒炎の支配者,201/165,SAR,A,シングル,12800,15800,9000,1,https://...,センタリング良好,1
```

カテゴリは `シングル` / `PSA鑑定品` / `BOX` / `サプライ`（または single / psa / box / supply）。

## 以前のバージョンから更新するとき

以前のバージョンで `schema.sql` を実行していた場合は、まだ実行していない更新SQLだけを一度ずつ実行してください（新しく作る場合は不要）。

```
cd worker
npx wrangler d1 execute pklabo-db --remote --file=./migrations/001_coins.sql      # コイン機能
npx wrangler d1 execute pklabo-db --remote --file=./migrations/002_pick_board.sql # パックを選んで開ける
npx wrangler d1 execute pklabo-db --remote --file=./migrations/003_allin.sql      # 残り全部引く
npx wrangler deploy
```

## コインと法律のメモ

- コインは「前払式支払手段」にあたる可能性があります。有効期限を6か月以内にしておけば資金決済法の適用除外です（管理画面の既定値）
- 6か月を超える・無期限にする場合、3月末・9月末の未使用残高（購入分）が1,000万円を超えたら財務局への届出と、残高の半額の供託が必要です。ダッシュボードの「未使用コイン（購入分）」で確認できます
- 当選カードをコインや現金に戻す仕組みは入れていません（オリパの換金性を避けるため）
